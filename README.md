Система предназначена для хранения и анализа событий интеллектуальных устройств (термостатов, датчиков), таких как включение, выключение, передача показаний и фиксация ошибок. Это позволяет техническому персоналу проводить мониторинг и диагностику неисправностей.
- **devices**: хранит информацию об устройствах.
  - `device_id` (INTEGER, PRIMARY KEY) — уникальный идентификатор устройства.
  - `name` (TEXT) — название устройства.
  - `location` (TEXT) — местоположение устройства.
- **events**: хранит журнал событий.
  - `event_id` (INTEGER, PRIMARY KEY) — уникальный идентификатор события.
  - `device_id` (INTEGER, FOREIGN KEY) — ссылка на устройство.
  - `event_time` (TEXT) — время события.
  - `event_type` (TEXT) — тип события ('включение', 'выключение', 'показание', 'ошибка').
  - `value` (REAL) — числовое значение (заполняется только для типа 'показание').
1. Убедитесь, что в директории присутствуют файлы `schema.sql` и `data.sql`.
2. Создайте базу данных и примените схему: `sqlite3 shop_devices.db < schema.sql`
3. Загрузите тестовые данные: `sqlite3 shop_devices.db < data.sql`
4. Проверьте работу запросов: `sqlite3 -header -column shop_devices.db < queries.sql`
По результатам анализа журнала событий чаще всего сообщает об ошибках устройство «Термостат-01», расположенное в Офисе 101 (зафиксировано две ошибки). Рекомендуется в первую очередь проверить его подключение и состояние, так как остальные устройства работают стабильно и не генерируют сообщений об ошибках.
