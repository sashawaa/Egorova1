## О проекте

Виртуальная система сбора и учёта данных на базе Arduino Uno для мониторинга технического состояния платёжного терминала. Система контролирует:

| Параметр | Датчик | Диапазон |
|---|---|---|
| Температура корпуса (s1) | NTC | 0-80 °C |
| Расстояние до клиента (s2) | HC-SR04 | 2-400 см |
| Состояние крышки (s3) | Slide Switch | 0 / 1 |

**Исполнительное устройство:** реле K1 (вентилятор охлаждения)  
**Индикатор:** жёлтый светодиод (10 мА, R = 300 Ом)  
**Период опроса:** T = 3 с  
**Порог события:** температура > 40 °C → включается вентилятор и светодиод

## Требования

Работа ведётся на Windows **без прав администратора**. Все программы — портативные и лежат в папке `%USERPROFILE%\tools`:

| Программа | Назначение |
|---|---|
| Git (PortableGit) | контроль версий |
| Node.js (LTS, .zip) | среда для Node-RED |
| Node-RED | загрузка данных в БД |
| SQLite (sqlite-tools) | работа с базой данных |

После распаковки программ выполни `env.bat` — он добавит их в PATH.

## Порядок запуска

### 1. Клонирование репозитория
```bash
git clone https://github.com/sashawaa/egorova.git
cd egorova
```

### 2. Настройка окружения
Дважды щёлкни по `env.bat` — откроется командная строка с настроенными путями.  
Проверь: `git --version`, `node -v`, `sqlite3 --version`.

### 3. Создание базы данных
```bash
sqlite3 db\variant.db ".read db\schema.sql"
```

### 4. Запуск Node-RED
Дважды щёлкни по `start-nodered.bat` и открой в браузере:  
http://localhost:1880

Импортируй поток из файла `nodered/flow.json` (меню ≡ → Import) и нажми **Deploy**.

### 5. Запуск симуляции в Wokwi
Открой ссылку на проект Wokwi, запусти симуляцию. Скопируй строки из Serial Monitor и сохрани их в `data/log.txt`.

### 6. Проверка загрузки в БД
После сохранения `log.txt` Node-RED автоматически загрузит данные. Проверь результат:
```bash
sqlite3 db\variant.db ".read db\queries.sql"
```

##Структура базы данных

**Таблица `readings`** — показания датчиков:
- `n` — номер измерения
- `t_s` — время от начала, с (t_s = n·T)
- `sensor` — s1 / s2 / s3
- `value` — значение

**Таблица `events`** — события системы:
- `type` — THRESHOLD / NORMAL / FAULT
- `message` — пояснение (например, «датчик s1 вне диапазона»)

## Оценка объёма данных

При периоде T = 3 с система формирует **86 400 показаний в сутки** (~3,46 МБ).  
За 30 суток — ~103,68 МБ, за год — ~1,26 ГБ.
